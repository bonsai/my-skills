# docs-driven-dev — ドキュメント駆動開発

ドキュメントで先に合意し、実装後に実態へ追従させる開発手順。

## 発動
- 「docs駆動で」「文書先行で」「仕様変えた→まず文書化」

## 手順
1. 変更の種類を判定 → 更新先:
   - 製品要求 → PRD / 設計・UX → spec / 技術方針 → ADR
   - 未確定の決定 → decision-options(選択肢+推奨+回答案)
   - 実行タスク → issue 登録(新規を上)
2. 人間の承認を得る(選択肢つきで質問。1行で決めさせない: 判断量・所要を併記)
3. 実装は TDD スキル(vitest)に従う
4. 完了後: STACK(実態)・kanban・recap を追従更新
5. commit(小分け・1行要約)

## 規約
- 実装より先に文書。破壊的操作・本番 deploy は承認必須
- 文書の信頼度: 実態系(実装後の事実)を最優先で正す。方針系(PRD/spec)は「構想」と注記
